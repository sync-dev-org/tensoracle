速さは上げる。

PyTorch の model を、TensorRT engine で速く動かす。その道のりを、tensoracle は一本の標準の手順と、手順で使う C++ の library にまとめました。

01 — 品質への安心

fp16 も fp8 も、
答え合わせを済ませてから。

減精度の engine は速い。でも、出力がずれていないかは、比べるまで分かりません。

  • fp32 は、本物の fp32。

    fp32 の engine は TF32 を使わずに組み立てます。答え合わせの基準そのものが、ぶれません。

  • 物差しは共通。線は、あなたが引く。

    画像の model にも音声の model にも、共通の尺度で出力を比べられます。

    非有限値の数最大絶対誤差相対 L2 誤差コサイン類似度許容誤差の外の数と割合

    合否の基準値と、PSNR のような model に固有の尺度は、用途を知るあなたが決めます。

  • int8 と fp8 も、同じ手順で。

    graph に置く quantize / dequantize の層と、safetensors で渡す scale から組み立てます。scale はあなたが用意します。

02 — 速さ

TensorRT の先は、
自前の kernel で。

標準の層では遅さが残る所だけを、CUDA C++ で書いた kernel に置き換える。kernel を TensorRT に差し込むまでの仕組みは tensoracle が持つので、あなたは、速くする計算そのものに集中できます。

一回の推論を、
CUDA Graph で丸ごと再生。

enqueue の一回を CUDA の stream capture で記録し、その graph を再生できることを、tensoracle が保証します。記録の前にすること、graph に固定される物、記録できない engine は文書で示しているので、迷わず使えます。

enqueue × 1→記録→再生再生再生…

scratch の memory は、
あなたが配る。

実行に要る scratch の device memory の大きさを問い合わせ、自分で確保した領域を渡して execution を作れます。同時に動かさない execution どうしなら、一つの領域を使い回せます。

scratch · あなたが確保→execution 1→execution 2順に使う

03 — 時間

同じ engine を、
二度と待たない。

TensorRT engine の組み立ては、起動のたびに繰り返したくない処理です。tensoracle は組み立てた engine を disk に保存し、process を起動し直しても、別の process からでも、同じ条件なら組み立てずに読み込みます。

条件が変われば、別の engine に。

重み、名前、graph の version、入力の形、GPU、TensorRT の version。どれかが変われば、別の engine として組み立てます。graph を変えた時は、名前か graph の version を変えるだけです。

壊れた engine は、読み込まない。

壊れた engine や条件の合わない engine は読み込まず、ほかの誤りと見分けられる誤りで返します。組み立て直すか止まるかは、あなたが決められます。

組み立てが落ちても、待ち続けない。

組み立てていた側が失敗した時は、待っていた側の一つが組み立て直します。process ごと落ちた時も、待つ側は止まったままになりません。

保存した engine の管理

溜まった engine は、
見て、選んで、片付ける。

一覧は、engine ごとに組み立ての条件、大きさ、記録時刻 (保存した時刻か、最後に開いた時刻) を示します。片付けは、消す前に、消す engine と、次に使う時は組み立て直しになることを示します。どちらも GPU を使わずに動きます。

片付けは、同じ置き場所で組み立てと読み込みが動いていない保守の時に使います。記録時刻は、その後も推論しているかを表しません。

04 — 手戻りの無さ

minor を上げても、
build し直さない。

tensoracle の C++ の公開 interface は、C の ABI を境界にしています。major version が同じ間は、前の minor の header で build した program と library が、後の minor の tensoracle でそのまま動きます。保存した engine の file の形式も、同じ間は互換を保ちます。

  • 推論の環境に、torch は要らない。

    重みは safetensors で受け取ります。torch は、.pth を safetensors に変換する時だけ、extra の tensoracle[convert] で入れます。

  • 重みは、GPU なしでも開ける。

    safetensors の file を GPU も CUDA も使わずに開き、tensor の名前、型、形、値と、header の metadata を読めます。

  • 静的に組み込むことも。

    共有 library に link するほか、source から build して自分の成果物に静的に組み込めます。静的に組み込んだ時は、更新の時に link し直します。

05 — 配布の楽さ

Linux も Windows も、
pip install から。

wheel には、C++ の header、共有 library、CMake の設定も入っています。tensoracle を source から build する必要はありません。

TensorRT は同梱せず、host に入れた runtime を読みます。

C++ だけで使うなら、build 済みの C++ の SDK を。OS ごとの archive を release ごとに配り、Conan の package としても取れます。

GPUNVIDIA の sm86、sm89、sm120fp8 は sm89 と sm120 で使えます。
OSLinux x86_64 (WSL2 を含む)、Windows x86_64
TensorRT11.2 以上、12 未満
精度fp32、fp16、bf16、int8、fp8
PythonCPython 3.12、3.13Linux は manylinux_2_28、Windows は win_amd64 の cp312-abi3 の wheel を、同じ version で出します。
